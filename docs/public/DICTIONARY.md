# 词典与纠正学习

## 识别提示

词条（以及已确认规则的正确拼写）随每次新听写、历史重新识别发送。本地识别和豆包云端支持词汇提示；不支持的适配器在历史中说明原因。当前客户端统一校验最多 128 词、4096 字符，含逗号或超限时报错提示，不静默截断。

豆包通过 `request.corpus.context` 传入 JSON **字符串**，内容为 `{"hotwords":[{"word":"mock"}]}`。最近添加的词优先排列：双向流式预览仅使用开头 100 tokens。有词典时启用 `enable_nonstream` 二遍识别，让最终结果使用提交的完整词典（服务二遍上限 5000 词，客户端上限更低）；这可能增加最终结果等待时间。没有词条时不发送 corpus、不额外开启二遍。

热词是概率提示，不能保证把合法英文词 mark 识别成 mock。确定的纠正需要确认词典中的替换规则；候选卡片直接显示纠正词对及原始输入，用户可直接添加关键词、接受替换规则或忽略。多字中文术语和英文规则保持原有整词/上下文行为；中文单字规则使用下述局部原句保护。

## 中文单字替换保护

单字汉字不是可全局替换的词。接受此类候选为规则时，自动使用已有原句片段，且片段中错误字只能出现一次；无法确定位置时保留候选，可改为接受词语提示。手动或程序添加此类规则也必须携带有效局部原句。候选界面不增加上下文输入流程。

执行时只替换命中的原句片段内该位置，片段在别处出现不会授权全文替换；片段不能嵌入更长的汉字串（如「他。」不得匹配「其他。」的后缀）。旧文件里的无上下文单字规则或无有效局部位置的单字规则保留可查看，但不再执行。保守地漏改优于误改其他词；多字中文术语仍能在连续中文中命中，英文仍保留词边界。

复验：`scripts/verify-integrity.sh` 通过生产 Propose → Accept → 保存 → 重开 → Apply 验证单字候选、歧义候选转词语提示、旧规则、其他/现在/正在、多字术语和英文词边界；同时验证词典保存失败不会留下半完成规则/候选。证据含每条原文、输出和独立 JSON 文件，不修改真实词典。

官方协议：[流式识别](https://docs.volcengine.com/docs/6561/1354869?lang=zh)、[热词与上下文](https://docs.volcengine.com/docs/DoubaoVoice/hot-words-and-context?lang=zh)。

## 修改观察

“从写入后的修改学习”仍默认关闭。启用后：

- 本地粘贴发出后立即开始读回，不等待剪贴板恢复。最多用 1 秒等待本次插入文本出现在唯一位置。
- 每 25 毫秒观察原输入框，在配置的观察窗口内（默认 30 秒、最少 5 秒）保留最新纠正快照；文本未变时不重复做差异计算。
- 发送导致清空、原区域丢失或停止可读时，使用此前最后一次纠正。新的消息不作为旧消息的纠正。
- 继续输入时，忽略有原文结尾作为锚点的纯尾部追加，只学习原文内的小范围替换。改回原文则不生成候选。
- 到窗口结束或发送时才生成候选，不把逐字输入过程中的半成品逐一写入词典。候选仍须用户确认；不自动启用替换规则。
- 仅观察原输入控件。远程输入、剪贴板回退不观察；不可读、重复出现的插入文本不猜测。输入框上限 4096 字符，差异计算上限每侧 1024 tokens。

边界：这是辅助功能读回采样，不是截获发送事件。若应用不提供 AXValue、在两次采样之间完成纠正和清空、或在首个原文快照前已修改，就不能恢复不可见的内容。此时可以在历史中修订。较大改写仍不学习。

## 可重复验收

`./scripts/verify-dictionary.sh` 编译并使用本机指定开发证书签名，启动独立原生输入框。需要桌面解锁以及运行器既有辅助功能权限，会短暂占用前台并恢复文本剪贴板。

验收使用生产 `macos.Insert → dict.Observe → Dict.Propose → dictionary.json → 重新打开` 链路：150 ms 纠正、450 ms 清空，早于 650 ms 剪贴板恢复；分别验证立即发送、追加长句再发送、撤销纠正、原文发送。前两项仅生成 `mark → mock` 一个候选，后两项无候选。产物为本地 `artifacts/dictionary-fix/native-results.json` 与各场景独立词典文件。

云端实际验收：`artifacts/dictionary-fix/acceptance --cloud --record <本机历史记录ID>`，使用当前已配置的豆包账号和原录音比较有/无词典。产物 `cloud-results.json` 分别记录协议完成与是否实际识别出 mock，不能把请求成功当成识别准确率通过。凭证不打印，个人历史和词典不修改；不提交私人录音及结果。

无需前台的补充验收：`artifacts/dictionary-fix/acceptance --protocol` 验证真实 WebSocket 首包序列化（空词典、Unicode、引号、顺序、二遍参数）；`--observations` 回放 12 种修改序列并验证词典落盘。它们分别生成 `protocol-results.json`、`observation-results.json`，不能代替原生输入框验收。

## 候选界面验收

检查候选、手动添加和词条的灰色圆角容器及搜索底色。候选显示原始输入与操作分隔线，不显示来源次数、上下文折叠或限定词输入框；使用独立测试词典验证两种接受操作、忽略和重启持久化，不修改用户真实候选。


## V2 原生词典页面

原生 `dictionary.go` 采用已确认 V2 的顺序：顶部「词典管理」页标题（24 pt、600 字重），其下为词语提示/替换规则/待确认数量与导入导出入口，手动添加，待确认候选，单列词条管理。标题与正文左对齐，随页面滚动；简体、繁体与英文使用对应语言标题。点击待确认数量滚动到审核区。

添加支持按钮和 Enter，成功后清空输入、返回全部类型与第一页；空值/换行不提交，重复项与容量限制仍由原词典逻辑处理。候选展示删除线旧词、加粗新词、来源/次数、冲突与原始句子；接受为提示/替换规则和忽略继续显式执行，未确认候选不生效。

词条按添加时间倒序，全部/词语提示/替换规则切换及搜索可组合；类型计数不随搜索变化。每行含类型、内容、已有上下文约束、创建日期，删除按钮悬浮或键盘聚焦显示。保留 100 条分页、候选 3 条分页及原导入导出语义，不迁移词典文件。

原生验收：添加唯一临时词（Enter），核对计数增加、清空输入和置顶；搜索定位，切换类型后确认正确空态，再回到全部删除该临时词，核对计数恢复与落盘。用现有规则只读检查上下文与类型筛选；不要接受/忽略用户的真实候选作为测试。导入/导出使用临时文件，取消文件选择不得修改词典。验收产物放本地 `artifacts/native-v2/`，区分已测与未测。

标题验收：打开词典并滚动至顶部，确认「词典管理」完整显示在统计行上方，与手动添加左边缘对齐；切换语言检查对应标题，统计及导入导出仍可见。

## 修改学习的短句边界（2026-10-20）

被动 `observed-edit` 必须仍有原文文字锚点，变更比例超过 35% 时不再享受六 token 的豁免；因此短消息整句替换不作为词语纠正。候选片段拒绝句子标点和多个撇号分隔的输入法拼音，仍保留常见技术词标点和有上下文的单字纠正。显式历史修订仍可把独立术语改为完整新写法。

限制只作用于“建议学习”，不拦截听写正文、不移除已有词条、不自动接受或恢复已忽略候选。它不能识别所有输入法的未提交状态；缺少可读辅助功能信息的应用依旧明确不学习。

`go run ./cmd/voice-quality-acceptance <新的证据目录>` 通过真实词典保存和重开检查普通术语、汉英纠正、短句改写、拼音片段、单字与显式修订；`go run ./cmd/dictionary-acceptance --observations` 检查观察生命周期。后者为读回序列回放，不等同物理键盘/中文输入法验收。真实原生输入框的补充验收沿用上方 `scripts/verify-dictionary.sh`。

## 手动配置、编辑与被动建议过滤（2026-10-23）

手动添加区可切换「词语提示 / 替换规则」。规则填写「原词 → 替换为」，可选上下文以中英文分号分隔；空格和逗号属于原句，不用于拆分上下文。中文单字的上下文字段显示「原句片段（必填）」，每个有效原句片段只包含一次原词。多字规则沿用任一上下文命中语义，英文沿用整词边界。

所有已保存词条提供「编辑」入口，回填类型、词对和上下文，并滚动到编辑区。保存和 Enter 共用校验；取消不修改词典。空原词、相同词对或含换行的词对不能提交；单字缺少有效原句、与另一规则冲突或写盘失败时保留草稿和原规则。编辑原子保存并保留 ID、创建时间、顺序和来源，避免改变规则执行先后。成功后清空编辑区、搜索和类型筛选，返回词条第一页。删除正在编辑的词条同时退出编辑。

被动学习仍是 AX 输入框快照加 token LCS 差异，**不是语义纠错模型**。旧版本把短消息整体改写、尚未提交的拼音、句末语气变化当作词对；已经落盘的候选不会因为新增生成条件自动消失。因此本轮将低质量检查同时用于新候选和待确认列表：

- 沿用被动修改必须保留文字锚点、变化不超过 35%、每侧最多六 token 的边界；LCS 每侧上限 1024 tokens。
- 过滤句子标点、多个撇号分隔的拼音片段，以及单个语气字参与的被动替换（如「呢 → 啊」）。这是学习入口的过滤，不改变听写正文和整理输出。
- 按原句片段重新检查旧被动候选的位置与变更比例；不确定位置不展示。原句中的汉英空格按原 tokenizer 比较，避免误过滤「V 六 / V六」这类既有记录。
- 只过滤待确认展示，不删除原始候选文件、不修改忽略状态、不动已确认词条。显式历史修订和手动规则继续可用，所有建议仍须用户确认。

已知边界：输入法未提交状态没有可靠的 AX 标记；短小内容改写可能仍与拼写纠正形似，中文差异片段也不一定是完整词语。过滤优先减少误学，不能声称其余建议都正确；不因次数为 1 就自动接受，更不自动覆盖同原词的不同规则。

### 可重复验收

先在本地 `artifacts/` 列出故障场景，所有写入均使用新建隔离目录：

```sh
go run -race ./cmd/dictionary-rules-acceptance artifacts/dictionary-rules-NEW
go run ./cmd/voice-quality-acceptance artifacts/dictionary-quality-NEW
go run ./cmd/dictionary-acceptance --observations
```

第一项经过生产 Add / Update / 保存 / 重开 / Apply / Delete，输出 `results.json` 和独立词典，覆盖上下文、英文边界、单字、冲突、写盘失败、旧候选过滤与原文件保留。第二项检查新增学习质量样本；第三项回放修改观察生命周期。它们不等于物理输入法验收。

原生 UI 夹具使用 `python3 scripts/build-development.py` 的独立开发签名包。将 `VOICE_INPUT_DICTIONARY_ACCEPTANCE` 和 `VOICE_INPUT_SEND_PREVIEW_ACCEPTANCE` 同时设置为同一个绝对证据目录再启动该包，数据定向到该目录的 `data/`，关闭听写热键，自动进入词典。仅开发包识别隔离数据根；不得对正式应用传递该夹具参数。操作步骤：

1. 切换替换规则，输入 mark → mock 与「产品;界面」，Enter 保存；核对计数、字段清空和落盘。
2. 编辑后先取消，核对原值；再次编辑为 MockUI，保存，核对原 ID / 顺序与新上下文。
3. 验证同词对禁用；单字「底 → 顶」缺原句报错，填写「放到底部的位置」后保存。
4. 切回词语提示添加词条，确认隐藏的原词/上下文不会混入；退出并使用同一夹具参数重开，检查持久化。
5. 保存 AX 状态、截图和 `dictionary.json`；真实已安装应用的候选仅只读审计，不接受或忽略私人候选作测试。

本轮证据：本地 `artifacts/dictionary-rules-20261023/`，与正式发布/安装状态分开报告。

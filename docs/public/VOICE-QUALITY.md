# 语音质量基线与迭代

本规格约束识别、整理、术语和修改学习的可重复验证，不以 API 成功或历史 `inserted` 状态代替文字质量、外部输入或消息送达。

## 冻结基线

在修改实现前保存失败清单，并冻结历史 ID、WAV 与 PCM SHA256、历史识别/整理、模型路由、已确认词典、格式选项、润色规则、源码与服务提示词哈希。凭证只从既有加密存储读取，不进入清单。

数据分为定向开发、留出和故障样本；留出样本只在候选冻结后评价，不用其结果继续调参。历史输出不等于当前基线，应先通过当前实现重跑同一录音。无音频或未完成的样本分别标注，不能换样本补齐成功率。

全零音频、弱信号、非零但未识别三者分开。全零录音没有可恢复的语音；非零并不证明存在可辨语言。没有逐字听音金标时，不报告 CER 或“识别准确率”。历史 ASR 和第三方润色也不是逐字真值。

## 三层对照

1. **录音 → 识别 → 整理**：走实际流式适配器、真实模型、服务计费回执和结果返回；保存原始 ASR、最终正文、错误及任务 ID。
2. **冻结 ASR → 整理**：对完全相同的文字分别运行旧/新提示词，区分识别改善与整理改善。输入不能使用期望正文。组合服务和独立整理分别验证。
3. **协议和状态**：真实 loopback HTTP/WS 检查词表摘要、旧服务拒绝、响应丢失取回；隔离存储检查修改候选和重开。它们不替代真实音频、麦克风、输入法或跨应用粘贴验收。

逐条评价实体/术语、动作、归属、数量、否定、条件、语气、位置、末尾补充、无中生有和把指令当请求回答；另列流畅度、重复与分段。词匹配仅用于提醒复核，不能自动判定语义合格。

## 运行器

`cmd/voice-corpus-acceptance` 接收本机私有 JSON 数组，字段为 `id/split/audio_path/audio_sha256/pcm_sha256/raw`。同目录放 `options.json`（`textStyle/polishRules`）及 `dictionary.json`。输出文件必须不存在。

```sh
go run ./cmd/voice-corpus-acceptance \
  -corpus /absolute/private-run/corpus.json \
  -output /absolute/private-run/results.jsonl \
  -variant frozen-candidate -hotwords
```

只有已部署配套服务时才能使用 `-hotwords`。隔离实例用 `-base http://127.0.0.1:38532`，服务本身只监听远端 loopback，经本机 SSH 转发连接。不要将验收端点暴露到公网。

`-cleanup-prompt <文件>` 仅用于带 `voicebenchmark` 标签的隔离服务，并要求显式 `-base`。该路径使用真实整理服务，省略 ASR 和用户语音钱包计费，仍消耗整理上游资源；报告不得把它算成完整语音旅程。正常构建不注册此接口。

```sh
go run -race ./cmd/voice-protocol-acceptance /absolute/new-protocol.json
go run ./cmd/voice-quality-acceptance /absolute/new-learning-directory
```

前者绑定本机 58198，检查词表传输、原配置未被修改、无词表兼容、旧服务在音频上传前拒绝、只 GET 恢复、全零不请求以及微弱非零不被拒绝。后者写入并重开独立词典，不接触用户词典。

## 时延与恢复

录音回放的总时间包含音频发送和模型等待，不能当作说完后的尾延迟。分别报告 `asr_after_last_audio`、`cleanup`、客户端完整结果及输入完成；真实硬件另测按键、采集、可见文字和剪贴板恢复。不同网络入口、背景负载和预热条件须披露，不能宣称严格控制变量。

纯全零 PCM 的重新识别直接返回无信号，不新建远端任务；实时路径在提交结束前检查并关闭流。现有声音、原文及失败记录按原隐私规则保留。服务响应丢失时继续查询原任务，不自动重录、换任务或向旧目标写入。物理静音、设备异常或缺失声音需要设备排查，不能用文本生成“恢复”。

## 交付与隐私

私人清单、录音、模型原文、逐条批注、HTML 与截图只放 Git 忽略的本机实验目录。报告提供音频播放、原历史/当前基线/候选对照、筛选、逐条结论和可复跑入口。检查数量、重复 ID、哈希、失败分母与音频链接，并实际验证浏览器播放和筛选。

修改模块规格及短入口引用，只提交通用代码、规范和不含私有数据的服务补丁。基线、隔离服务验收、原生验收、正式服务部署和客户端发布分开报告。

## 第二轮质量与时延门槛

- 同一录音先保存不变的 WAV/PCM 哈希。上游候选可以使用按采样更新、每会话独立的峰值包络增益：只增强低声、不衰减足够响的声音、不裁剪、不增加缓冲。历史原音、任务幂等音频摘要不变；增强音频不是原始录音，报告须注明。
- “实时/试试”“组件/途径”等近音词必须以原录音连续多轮检查，另有本来就说“试试”“途径”的反例，禁止加入基准专用全局替换表。合成音仅用于反例，不能计入真实用户样本成功率。
- 非零空结果分别记录信号幅值、语音活动及独立识别证据。没有可辨语言时保留失败和原录音，不能把噪声拟声词算成恢复成功；模型/VAD证据不等于人工听音金标。前台提示“未识别到语音，请靠近麦克风”，纯零仍提示设备没有录到声音。
- 已确认替换规则以最小快照进入云端；候选、历史 ID 和学习来源不发送。英文词边界、上下文条件、单汉字原短语范围及规则应用顺序与本地相同。原始 ASR 原样保存；纠正只在整理输入、计费前执行。关闭整理仍交付原始 ASR。
- 明确“第一/第二/第三”“1、2、3”等事项序号，每项必须实际换行，并优先保留原有分项边界。同一项的两个形容词不拆成两项；版本、日期、价格、计量和代码不当成编号。无编号单段保持单段，原有段落保留，不因长度或多个要求自动分组，保留可能、似乎、否定、归属和末尾要求；短请求不得回答。不以输出拦截或强制重试掩盖模型失败。

每次提示词变化都冻结 SHA，候选冻结后才打开新留出。已经看到结果的留出只能作为回归样本，不继续声称盲测。配对回放须同网络入口、交替顺序、串行运行；分别记录 ASR 尾部、整理与二者之和的 P50/P95。至少对关键术语和编号样本重复三轮，失败全部保留。硬件采集到外部粘贴未测时明确标注。

发布前：逐条关键内容无新增退步、明确编号稳定换行、长文忠实且流畅、非零空结果有恢复或无语音证据、延迟达到本轮预先定义门槛，并完成原生相关回归。任一硬门槛未满足，保留实验和可审查代码，正式服务及客户端不更新。先部署兼容的新服务，再按正式签名、公证、票据和安装验证流程发布客户端；模型接口成功不是质量验收通过。

本轮候选结果：明确编号和已确认规则验收通过，但近音词重复复测仍有失败、部分长文仍有冗余，配对时延也未稳定改善，发布门槛为 `NOT_MET`。因此不提高客户端正式版本、不部署服务、不发布安装包；后续不能用一次成功覆盖保留的失败记录。

用户随后指出无编号长文被过度分段；该结构应判为失败，之前把强制分组计为改善的结论作废。后续配对回归须同时检查无编号单段不拆分、明确编号逐项换行，保留旧输出，不以新一轮结构通过替代近音词与时延等未达标项。

## 含糊字串与延迟续测（2026-10-20）

只增加陌生实义字串内部重复的保留约束，不扩展整理范围。沿用 9 条历史 ASR 加 2 条合成探针、各三轮的开发集，以 `5d6c6e3` 为配对基线，结构两侧均 33/33，问题字串保留由 0/3 到 3/3；仍有口语残留，且两例相较基线出现句架冗余、碎句标点的流畅度退步；不能称质量无退步或泛化准确率通过。

交替顺序、持续连接及共享负载快照补齐后，首个请求另列，余下各 32 次：基线 P50/P95 为 701/1089 ms，最小修复候选为 751/966 ms（nearest-rank）。首条及一个候选请求有并发干扰，原始值全部保留；去掉受干扰配对的 31 对敏感性统计为 701/1089 与 750/952 ms。典型延迟仍回退，预先定义的 P50 和 P95 均不回退门槛未满足，发布状态继续为 `NOT_MET`。

两个历史“实时”录音另跑三轮完整链路，成功重试批 6/6 保留；之前通道故障和历史识别失败不删除。因整理延迟门槛未过，本轮未继续完整 54 条录音与原生旅程验收，未更新正式服务、模型运行参数或客户端。两条整理路径不可互相替代：云端压缩提示词试验未达标，保持既有提示词。

## 流畅度续测与实际路由校正（2026-10-20）

“仍有退步”描述的是实验候选与冻结基线的逐条差异，并不表示已安装应用更新后退步。实查应用选择 sub2api 组合识别/整理；前节本地 Qwen 独立回放的时延不能当作该日常云端路由的成绩。验收输出的路由归属见[整理规格](../../internal/cleanup/README.md#实际路由与实验归属)。

沿用同一 11 条开发样本，各三轮交替对照原始 `5d6c6e3`、上一轮 `66a4ccd` 和私有 M 候选。M 修复上一轮孤立碎句、减少另一例冗余，但另一个长句出现不自然句架，整体仍不满足无退步。三版本地结构检查均 33/33，含糊叠字保留为 0/3、3/3、3/3；结构和词匹配仅为复核线索，不等于语义通过。

首条另列后各 32 次，本地 P50/P95 为 716/1135、728.5/963、805.5/1403 ms。P50 使用通常中位数，P95 使用 nearest-rank。保留全部慢值；去除观察到共享并发的完整配对后，31 对敏感性统计为 711/1038、722/949、800/1403 ms，仍无提速证据。试验性的 ANE 配置及关闭推测解码没有证明可靠收益，不改变现用模型参数。

另外将当前正式云端提示词快照与既有候选放在同一隔离适配器上，各做 33 次真实上游配对。服务端整理 P50/P95 为 742/1084 与 796/1449 ms，客户端往返为 832/1173 与 895/1538 ms。候选仍有含糊字串遗漏、编号样式及分项边界问题；上游负载不能完整观察，此数据不是生产 ASR 到粘贴的全链路测量。

进一步精简提示词、输入预排和最小提示词差异实验也未同时通过质量与延迟检查，均不采用。本轮产品整理行为不改，公共代码仅补齐验收路由标注；未重跑完整 54 条录音和原生旅程，不部署正式服务或发布客户端。私有原文、失败输出、输入版本、逐条复核、哈希和浏览器报告全部保留，发布门槛继续为 `NOT_MET`。

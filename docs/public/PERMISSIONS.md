# 权限拖拽引导

实现入口：`permission_drag.go`、`internal/macos/file_drag_darwin.go`、`internal/macos/settings_window_darwin.go`。

- 首次引导与设置 → 权限共用同一个非激活原生面板，适用于辅助功能与输入监控。麦克风仍使用系统授权请求。
- 面板展示当前运行的 `.app`，拖拽使用真实文件 URL 与 copy 操作，不移动应用文件。非应用包运行时显示说明，不提供无效拖拽。
- 正常情况下卡片位于系统设置窗口外下方 10 点，与右侧内容区右边对齐；跟随窗口移动、缩放。空间不足时依次尝试右侧、左侧、上方；全屏占满可用区域时退回屏内底部。箭头随位置转向，侧边／上方使用不含“上方”的提示。
- 从窗口服务器读取几何信息，无须预先授予辅助功能或录屏权限。每 200ms 跟踪一次，仅在授权流程活动时工作；首次等待窗口最多 8 秒，窗口消失持续 1.5 秒后关闭。
- 面板不抢键盘焦点。拖拽期间淡出，来源窗口保留鼠标事件；AppKit 原生来源视图负责跨窗口拖放。目标确认接收应用文件后立即收起；取消、无有效落点或失败时保留面板并恢复鼠标交互。收起面板不代表授权成功，首次引导与设置页仍以系统权限状态为准。
- 每秒读取权限状态，授权后显示成功约 0.9 秒并收起，同时刷新首次引导与设置页。面板可以手动关闭，再次点击授权入口可以重新打开。
- 支持英文、简体与繁体中文；沿用客户端外观设置，包括跟随系统。深色模式提高箭头亮度；卡片使用靛蓝／薄荷绿外侧柔光，无彩色描边。减少动态效果时停用呼吸动画，高对比度时补充清晰轮廓。

## 原生验收

1. 日常使用固定 Developer ID 构建；调试使用独立开发身份。核对当前安装与验收包的 Bundle ID、签名及 designated requirement，禁止以开发包覆盖正式包。常规验收不得重置用户 TCC 以制造未授权状态。Steve 已要求 zoppo-macmini 后续干净重装／首次授权验收先清理 Voicemore 的旧授权；该场景按下节执行，不影响其他应用。
2. 分别从首次引导和设置页打开辅助功能、输入监控，验证同一个面板、正确系统设置页、真实运行包路径。
3. 移动／缩放系统设置；验证跟随、窗口外 10 点间距、多显示器和屏幕边缘回退。
4. 实际拖拽、取消与重试；验证系统设置保持焦点、跨窗口原生拖动、目标接收应用文件而非文本。成功落点后即使权限状态仍未刷新也应立即收起；取消或落到无效位置必须保留面板。
5. 在未授权的独立验收环境中完成真实授权，验证状态更新与自动收起；已有授权机器可用本地验收 overlay 检查原生布局，不得将模拟状态记为真实授权通过。
6. 中英文 × 浅深色截图，检查换行、箭头、柔光和关闭按钮。验证关闭系统设置、关闭面板和重新进入，不残留悬浮窗。
7. 将签名信息、运行命令、截图与未验证项保存在本地 `artifacts/permission-native/`，不入库。

## Mac mini 干净授权验收

- 删除应用包不等于删除授权。发布签名切换到开发签名时，同一个 Bundle ID 的旧权限开关可能仍开启，但旧签名要求不适用于新进程。
- 干净重装／首次授权测试前，记录现有签名与运行路径，仅针对 `dev.steve.voice-input` 执行 `tccutil reset Accessibility dev.steve.voice-input`、`tccutil reset ListenEvent dev.steve.voice-input`、`tccutil reset Microphone dev.steve.voice-input`；禁止不带 Bundle ID 的全局重置，禁止直接修改 TCC 数据库。
- 通过系统设置重新添加当前 `/Applications/Voicemore.app` 并开启辅助功能、输入监控；通过应用请求麦克风授权。按系统提示退出重开应用。
- 以重启后的应用三项状态及实际听写结果确认成功，不能只看系统开关。保留设置、历史与模型数据，除非另有清空授权。

## 系统开关已开但当前应用仍未授权

开发签名与 Developer ID 正式签名之间切换时，macOS 可能保留旧应用名称和开启的权限开关，同时以旧代码签名要求拒绝当前进程。以当前运行包的签名、应用内实际权限和系统日志为准；日志中 `Failed to match existing code requirement` 可确认此类身份不匹配。

针对当前 Voicemore，在输入监控与辅助功能各自的列表里选中旧条目，点减号移除，再点加号选择实际运行的应用包。不能只重复拨动旧开关。输入监控按系统提示“退出并重新打开”，随后检查应用内两项均为已授权、当前 HID 监听启用，并实按 Fn 开始/结束。此操作仅刷新 Voicemore 已有授权，不清除历史、设置或其他应用授权；不需全局或定向重置 TCC。

## 原生拖动会话恢复（2026-10-17）

应用卡片使用透明 AppKit 来源视图，在真实 `mouseDragged` 回调内同步创建会话，并直接以当前应用的 `NSURL` 写入拖动项。不再经 UI 框架延后启动或临时鼠标穿透；开始前检查左键仍按下，防止积压的移动事件在释放后创建等待下一次 mouse-up 的会话。拖动图像使用当前应用文件的系统图标，仅允许 Copy。

卡片的窗口跟踪与权限检查由独立 200ms 轮询驱动，拖动中也能发现系统设置消失。鼠标已释放且业务层完成回调迟迟未到时恢复卡片交互；不能仅凭该回退认定目标已接收或授权成功。关闭、换授权入口或重开时禁用旧原生来源并隔离旧代次；完成回调离开 AppKit 回调后再更新或隐藏窗口。原生来源视图仅在布局或启用状态变化时调用 AppKit 更新，避免连续 AX 通知影响操作响应。

复验须同时包含成功接收真实 app URL、无效落点、快速释放、关闭重开、丢失业务回调、鼠标仍按住时不误收尾；保存原生生命周期与主线程响应证据。自动投递的鼠标移动可能没有物理按下状态，按下保护拒绝这类事件不能算作真实拖入成功。

## 常规更新保持授权身份（2026-10-17）

本地安装、正式分发与自动更新共用 [签名策略与隔离规则](DISTRIBUTION.md#unified-signing-identity-2026-10-17)。自动安装前必须同时满足固定 Developer ID 团队、Bundle ID 及旧版 designated requirement；不兼容时保留旧包，不通过换签、TCC 重置或重复授权绕过。开发版独立名称、Bundle ID、数据目录且无正式更新源。

已有同 Bundle ID 的跨团队开发修复包属于遗留迁移，不能保证静默继承正式版授权；不得把这类一次性迁移当成每次升级都要授权的正常流程。正常同身份更新应保留现有权限；系统主动撤销授权、用户重置或手动换签不在此保证内。

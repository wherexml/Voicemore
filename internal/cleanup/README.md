# 文字整理模块规格

当识别模型为 sub2api 时，整理由同一云端任务完成，客户端不调用本模块或直连 DeepSeek。服务端仍执行整理；客户端总开关选择交付原始识别或整理正文，保留计费回执且不做第二次格式改写；见下文原生文字整理总开关。单独重新整理及翻译暂不支持。协议、计费回执和复验见[云端 ASR](../cloudasr/README.md#voicemore-officialsub2api-组合服务)。

文字整理默认关闭，使用独立于 ASR 的 OpenAI 兼容接口。`Run` 向 `/chat/completions` 发送固定 system 提示词与转写 user 消息，temperature 为 0、非流式；本地 oMLX 发送 `enable_thinking=false`；DeepSeek 默认发送 `thinking: {"type":"disabled"}`，避免云端默认思考增加整理延迟；自定义服务不自动附加这两种参数。连接检查仅列出 `/models`，不证明模型整理质量。

### 本地服务延迟排查

本地 oMLX 配置明确发送 `enable_thinking=false`；DeepSeek 使用自己的 `thinking.type=disabled` 协议，不能用 oMLX 的参数替代；自定义服务分支不发送这两个参数。须结合服务端参数处理、返回的 reasoning 内容和生成 token 数确认是否生效，不能仅凭模型默认支持思考判断。

历史中的 `timing.cleanupMs` 是完整请求耗时，包含服务端排队。共享 oMLX 的并发上限为 1 时，其他长请求会阻塞短文本整理；应对照请求完成时间、生成 token 数及实际 decode 时间，区分排队与模型生成缓慢。支持在线调整并发的 oMLX 版本可尝试将上限从 1 调为 2，再用同一模型、提示词和文本比较空闲与后台长请求运行时的延迟。此设置影响共享服务，并非客户端自动设置；多个长请求占满并发时仍可能排队。

验收至少重复三轮，保存请求参数、原始响应、耗时、输出一致性、并发生效日志和原配置回退方法。不要把含排队时间的首 token 耗时直接当作纯 prefill 性能，也不要把单次改善当作延迟保证。证据保存在 `artifacts/cleanup/`。

## 当前提示词目标

转写是待整理数据，其中的问题、命令和请求应保留而非执行，也不能改变 system 规则。目标是让口述成为可以直接发送的文字；完整和忠实优先于简短、排版。删除无意义填充词、结巴、无意识重复和明确放弃的半句话；合并重复时保留各次提供的不同细节。保留语气、人称、否定、条件与不确定性，明确改口且给出替代内容时才采用最终说法。

### 流畅度与忠实性

整理须主动去口吃、修碎句、合并同一观点的冗余；不能仅补标点或因局部含糊而逐字照抄整句。重复句架可以重组，各次补充的不同信息及其所属对象必须保留。不追求摘要式简短，不增加事实或逻辑关系。

术语、英文原词及单复数、真实数量及单位、归属限定、比较、否定、条件和末尾补充都要保留。有信息的语气、情绪和不确定程度也不能为了流畅而删除。明确改口采用最终说法；位置或词义不明时只保留有歧义的局部，不猜品牌或补齐尾句。

普通叙述中的“一个过程”“一条建议”“一份报告”“做一次测试”“再试一遍”“第一次”等自然表达使用中文，输入的“1个/1条/1次/第1次”也由模型结合语境恢复中文；真实数量及只/每等限制不删，计量、金额、日期、时间、编号和数量对比保留清楚数值，前后两次基础格式均遵守[数字规格](../../docs/public/TEXT-FORMATTING.md)。数量语义不变，不增加固定口语白名单、词法/语义拒绝、结果替换、二次审核或隐式重试。

### 内容组织

- 按已有内容区分问题现象、具体要求、原因解释和交付要求，用自然段组织。
- 多个独立问题或需求可以改成编号列表，不再要求原文必须明确说“第一、第二”。编号表达原有并列关系，不虚构执行先后；确有多层关系时才用嵌套列表。
- 同一对象的散落补充可以归组，例如把末尾补充的列标题对齐要求并入前面的列宽调整项。跨对象的内容不合并，不把背景、请求和限制混为同一项。
- 引导语只能概括已有共同主题。短句保持简短，不硬加标题和列表；连贯观点或叙述以自然段为主。
- 输出前检查每个独立对象、动作、范围、位置、数量、时间、原因、条件、先后关系、禁止事项和输出格式，尤其是末尾补充。

不得补充事实、虚构分类或改成客套书面语；保持原文语言和中英混合，数字、日期、专名、代码、路径、英文写法应保留。只对有充分上下文支持的普通同音错字作修正，有歧义时保留。ASR 已缺失或中断的内容不能依靠整理恢复，禁止按常识续写尾句、猜测技术词或补造需求。

输出只含正文，不附解释、总结、代码围栏或包裹全文的引号。实际质量取决于所选模型，提示词不是确定性转换器。

## 返回行为与已知边界

协议完整性检查：`finish_reason=length` 明确表示输出达到上限，即使正文非空也返回 `ErrTruncated`，不写入半篇结果；保留原文及显式重试/使用原文操作。最多读取 4 MiB 加一个探测字节，超过限制返回 `ErrResponseTooLarge`，不再误报无正文；恰好 4 MiB 的有效响应仍可采用。未提供 finish_reason 的兼容服务和 stop 保持原行为。普通整理、翻译、重试和历史重整理共用此检查；失败不追加成功历史版本，无隐式重试，不修改提示词或增加语义拦截。

复验：`scripts/verify-integrity.sh` 在本机五位端口 58196 通过真实 HTTP 与生产会话代码验证 length、空截断、超限、恰好上限、空/无效正文、传输中断、超时/取消及 stop/缺字段兼容；验证失败保留原文、不进入写入、显式重试只输出一次、使用原文和历史版本落盘。阶段注入与 practice sink 不代表真实麦克风或跨应用粘贴。

用户要求整理不要因词法校验失败：有效模型正文直接采用，移除数字/英文 token 检查、固定短语白名单及 `ChangedError`。不新增语义拦截、二次模型审核或隐式重试。空模型、无效 URL、网络故障、非 200 响应、无有效正文仍返回真实错误，保留原始转写；超时与取消继续分别提示。旧历史错误文本不回写。

口语“一个/1个”由整理模型结合上下文处理：只是引入想法、感受、效果且省略不改变数量时可自然省略；购买、分配、数量对比、唯一性或只/仅/每等限制中的数量与单位须保留；不确定就保留。不依赖固定短语名单，不将全部“一个”统一删除。

忠实性要求逐句保留有信息的分句，包括参考对象的现状、自己的目标、归属代词、比较关系、否定、条件和末尾补充。采用轻量编辑而非摘要，不因后面的需求重复某个属性就删除前面的参考描述。真实数量、日期、英文、路径保持含义和对象对应。

提示词不能保证任意模型的语义忠实性；运行时不以词法或语义检查阻止输出。原文保留可查看，质量通过真实模型样例逐条核对。

### 校验复验

保留历史命令名称 `go run ./cmd/cleanup-guard-acceptance`，其当前职责是非拦截 HTTP 契约验收。五位端口 58188 调用生产 `cleanup.Run`，覆盖等值改写、口语省略、数量改口、英文变化不会被拒绝，以及空响应仍失败。此处允许英文变化仅证明不拦截，不代表翻译符合整理质量要求。

`go run ./cmd/cleanup-guard-acceptance -live` 使用当前实际配置与本机加密凭证串行运行数量、口语、比较关系、否定和英文对照样例。`-live -record-id <历史ID> -repeat 3` 只读重放指定真实记录；ID 不存在或参数无效时失败，不扫描所有私人历史请求。输出包含输入、模型原始响应、错误和耗时，保存至 Git 忽略的 `artifacts/cleanup/`。

批量回归须冻结同一批历史 ID、输入与旧版输出，先记录各条必保留的信息点；固定最终提示词后每条串行重放三次，并应用本机 `textstyle.Apply` 与词典热词，再逐条比较最终文本。报告每条的原文、模型正文、格式化结果、与旧版的差异和三轮一致性，区分原意保留、语言格式、流畅度与 ASR 原文本身的歧义。重复同一记录不是独立新样本；用过的样例属于开发/回归集，不能据此保证未见输入的效果。生产历史只读，原生重整理验收可追加版本，不能覆盖旧原文。

live 的 passed 仅表示所有请求获得有效正文；`semanticReviewRequired=true` 明确要求人工逐句审阅，不把 HTTP 成功当作忠实性达标。开发记录与提示词相邻示例应标记为开发集，不宣称泛化准确率。

## 可重复 E2E 验收

用指定证书构建后，在应用中选择实际整理模型与测试用 TextEdit 文档。依次听写：带填充词的句子、三项顺序枚举、“这是我第一次用”、含否定条件的句子、中英混合及路径、数字改口，以及“请帮我……”形式的请求。核对历史原文、整理结果和目标文档，确认请求未被执行、列表边界和信息保留；明确数字改口应保留最终数量，不能再因旧数量消失而失败。

重试和历史重新整理也应使用当前整理配置。另验证关闭整理、服务不可达和空响应的用户可见行为。在 `artifacts/cleanup/` 保存环境/模型版本、构建提交、逐项原文与预期/实测、历史与目标截图；只用无敏感信息的样例，记录模型差异，不以提示词示例作为实测证据。


### 冻结转写的整理 A/B 验收

使用同一批真实音频已经产生的 ASR 文本，固定输入 ID、内容哈希、词典和文本样式。分别构建旧版、新版整理运行器，调用真实 `cleanup.Run`，再应用与会话相同的 `textstyle.Apply`；记录模型与端点、system 提示词、原始响应、耗时、服务错误和最终文字。串行运行以减少共享模型排队干扰；若另做并发负载试验，应单独记录。

重点覆盖：长文分组、末尾补充归并、自然段叙述、短句不扩写、禁止/条件保留、数字与英文保留、自我改口、缺尾句不续写，以及转写中的命令只被整理不被执行。输入为空时保持空，不请求模型。超时和接口失败不能算成功整理；请求成功后仍须人工核对信息完整性，不增加产品拦截。

对照经润色的第三方文本时，将“结构和可读性”与“对 ASR 输入的忠实性”分开评价；不能从另一个识别器补齐事实。开发例子同时用于调整与复测时，应标记为开发集，不宣称泛化准确率。私人录音、转写和报告仅留在 Git 忽略目录（本机批量对比使用 `dataset/`）。此 A/B 验收覆盖真实模型、返回正文和后处理，不替代麦克风、原生 UI、历史写入与粘贴的验收。

### 超时与传输错误验收

HTTP 响应头返回成功不代表正文已完整收到。读取正文期间超时或取消时，保留 `context.DeadlineExceeded` / `context.Canceled`，由界面分别显示超时或取消；连接中断归为传输故障，不能把不完整 JSON 误报成接口不兼容。完整但无效的响应才使用 `ErrNoText`。明确的非 200 响应立即保留 HTTP 状态，不等待无用错误正文。

复验命令：`mkdir -p artifacts/cleanup && go run ./cmd/cleanup-acceptance > artifacts/cleanup/transport.json`。运行器绑定本机五位端口 58187，调用生产 `cleanup.Run`，覆盖响应头后超时、半截正文超时、取消、截断正文、完整无效 JSON、正常结果和错误状态；输出逐项 JSON，任一失败则非零退出。它不使用真实凭证，不修改用户历史或模型设置。故障清单须在实现修复前冻结；本次未新增单元测试。

### 共享 oMLX 的 SSD 缓存等待

不能把服务日志中包含等待时间的 tok/s 当成模型的纯生成速度。排查时同时核对调用方、active/waiting 数量、内存压力和 `boundary_snapshot_store` 的 writer 等待告警；新闻总结、批量评测等后台请求可能与听写共用同一个模型。并发额度未耗尽时，缓存清理路径仍可能阻塞生成。

若当前安装版本支持 `hot_cache_only`，可在保存原缓存参数后测试内存缓存模式，例如 `hot_cache_max_size=8GB`、`hot_cache_only=true`、`hot_cache_write_through=false`、`gdn_snapshot_storage=auto`。这是共享服务的可选调优，不是客户端默认配置：会停止使用 SSD 缓存，并可能降低重复提示词的缓存命中率。现有 SSD 文件不需要删除。须验证并发尾延迟与空闲耗时的取舍；不能只报最好的单次结果。

管理接口应用缓存配置可能卸载所有已加载模型并中断请求。必须先让已授权暂停的后台调用停止提交、等待 active/waiting 清零，再调整并重载。验收完成后恢复所有暂挂任务，并确认结果继续增长；运行中的批量对比若跨越配置切换，须明确标记性能条件发生变化。对照必须冻结提示词、模型、输入与背景负载，保存持久配置及运行日志；其他任务介入的轮次单独标注，不能声称严格控制变量。

本机可用的回退方式是通过原管理接口恢复事先保存的缓存字段，再等待模型重载；不要覆盖整个 settings.json，以免回退其他任务的配置。

### 冻结真实记录的流畅度对照

`go run ./cmd/cleanup-quality-acceptance -corpus <本机冻结JSON> -repeat 3` 接收包含 `id/raw/previous` 的私人样本文件，串行经过生产词典、基础格式、真实模型和最终基础格式。输出 JSONL 包含实际模型输入、正文、最终文字、旧结果、耗时和错误。先构建旧版运行器、冻结同一份输入，再与新版逐条对比；人工分别记录原意/术语/数量、语气/歧义及流畅度，不把有效正文或三次一致当成质量通过。样本与报告仅保存在忽略目录。

### DeepSeek 默认关闭思考与分组保留

所有普通整理、重试、历史重整理通过 `providers.CleanupOptions` 为 DeepSeek 设置关闭思考；不改用户已选模型，不改变自定义兼容服务。仅改变请求参数，无额外调用或语义拦截。官方协议见 https://api-docs.deepseek.com/guides/thinking_mode/ 。

长文涉及不同对象时须实际以空行分段；并列要求可连续编号，整体背景和交付要求放在列表之外。只有归属明确的补充才归并，不虚构菜单层级、原因或标题；连续叙述与短句不硬套列表。

含糊字串、疑似识别错误及孤立实义字保留在原上下文；附近出现相似的正常术语不能作为替换依据，也不能因含糊而当作重复删除。周围明确内容仍清理口吃并分段。该约束由提示词引导，不能保证所有模型输出都满足；逐条复核结构、限定、数量、英文、歧义和残句，不增加白名单或拒绝机制。

协议验收：`go run ./cmd/cleanup-thinking-acceptance`，通过本机 58189 HTTP 服务检查 DeepSeek、本地、自定义三条配置路径的实际请求，输出逐项 JSON，失败非零退出。真实模型回归使用 Git 忽略的 `artifacts/cleanup/deepseek-default-20261016/`，原10条加4条新增边界案例各3轮，保留请求、输出、耗时及人工审阅；这是模型/API验收，不替代麦克风和粘贴验收。

### 自定义服务的思考模式

自定义文字整理服务的高级设置支持四种模式：跟随服务端（默认，旧配置缺字段也如此）、关闭·DeepSeek 协议（`thinking.type=disabled`）、关闭·oMLX 协议（`enable_thinking=false`）、自定义参数（JSON 请求体字段）。同一服务内的模型共用配置。切换模式保留参数草稿，但只发送选中模式的参数；保存时持久化，取消不保存。自定义 ASR 不显示这组设置。

参数必须是最多 16 KB 的 JSON 对象，自定义模式不接受空对象。禁止覆盖 model、messages、stream、temperature、工具调用等应用核心请求字段，禁止凭据、请求头及嵌套凭据字段。凭据仍由独立 API Key 输入及本机加密存储管理。非法参数或未知模式会明确失败，不能静默忽略。自定义字段随整理正文请求发送，不附加到 GET /models。

“测试连接”仍只列出模型；“测试整理”使用当前未保存草稿、测试模型选择及固定无敏感示例发送一次真实请求，30秒超时，展示返回正文与耗时，不修改默认模型或历史。编辑端点、密钥、模式、参数或模型后旧结果失效。成功表示接口返回正文，不证明服务端没有内部推理；供应商可拒绝或忽略参数。

验收：`go run ./cmd/custom-thinking-acceptance` 在本机58190通过真实HTTP验证保存重开与15种协议/无效参数场景。真实服务对比、原生设置保存/重开/取消与测试按钮证据存于 `artifacts/cleanup/custom-thinking-20261016/`，不入Git；不新增单元测试。

### 组合云端服务的明确同音纠错

sub2api ASR 2.0 组合服务由服务端独立提示词整理，允许明确上下文中的中文同音纠错，同时保留仍含糊的事实；不使用全局替换或输出拦截。该规则与直接整理服务各自的提示词配置分开，详见[云端语境纠错](../cloudasr/README.md#云端整理的语境纠错2026-10-18)。

## 原生文字整理总开关（2026-10-18）

设置 → 文字与粘贴顶部为“文字整理”分组，第一行为“默认整理文字”；听写页移除该行。总开关关闭时基础格式五项及润色规则展开按钮、编辑框禁用，Tab 跳过；重新开启恢复保存值。润色规则及展开状态随设置保存，空规则也保留。规则作为附加用户偏好传入独立整理模型的 system 提示词，保留原有忠实性约束；不传入翻译请求。

关闭时普通识别结果跳过客户端词典、基础格式和独立模型整理，原样交付识别正文。按会话开始时的整理选择执行，不在处理中反向覆盖。首页、菜单栏及设置使用同一选择，服务不可用不会强制改写用户开关；开启后的真实服务失败仍展示错误。

组合云服务 sub2api 允许选择交付 `raw_text` 或已整理的 `text`，仍保留完整整理正文及计费回执；关闭不代表服务端停止整理或免除费用。基础格式和润色规则与其他服务一样可设置：随当前录音传入云端，服务端执行后按最终正文计费，客户端确认选项回执后才发送音频。控件仅随总开关禁用，不按服务商禁用。历史重新识别遵守当前开关，取回已有云端结果不覆盖原记录的整理选择。

验收：`go run -race -tags textcleanupacceptance ./cmd/text-cleanup-acceptance <全新证据目录>` 使用五位端口 58197、合成转写、真实本机 HTTP 和生产 finish/clean/practice sink 验证关闭原文、开启格式及规则请求、云端回执保留和设置重开。它不证明物理麦克风、外部粘贴或真实云端调用。开发签名隔离应用点击、规则编辑、切换分类、关闭后 Tab 跳过、重启保存及截图见本机 `artifacts/text-cleanup-native/`。

### 润色规则编辑区细节（2026-10-18）

标题、展开按钮与编辑器合并成一个内边距 14 DIP、间距 12 DIP 的区域，移除标题与输入框之间的分隔线。展开按钮为 28 DIP 高圆角控件，使用共享上下箭头；保留键盘焦点及 Space 操作。输入框固定 176 DIP 高，13 DIP 字号、22 DIP 行高、12×14 DIP 内边距、10 DIP 圆角，浅深色均显式设置背景及常驻边框；沿用原生编辑控件的选区、撤销、输入法与内部滚动。长文不增加页面高度。禁用仅作用于实际控件，避免父子重复淡化；禁用按钮不展示键盘焦点圈。

复验：浅色和深色分别检查未聚焦/聚焦/禁用；粘贴 24 行含中文及英文的规则，确认末尾光标可见且编辑器内部滚动，Cmd+Z 恢复；Shift+Tab、Space 收起再展开，确认内容及焦点保留；总开关关闭后编辑器和按钮不可用。原生截图与可重复步骤见本机 `artifacts/polish-editor-refinement/`。

## 独立信息与短指令基线（2026-10-20）

整理按独立功能、动作、接收对象、禁止项、条件和末尾补充逐项对照。列举后的能力补充不能只剩列表外壳，短问句不能当填充词；明确改口且有替代内容才删除旧说法。普通中文句架可修顺，清楚的短指令不扩写、不代答。组合服务与独立整理仍是两个独立提示词入口，两条路径分别验收，不以一条的结果代替另一条。

`cmd/cleanup-quality-acceptance -standalone` 明确选择已保存的独立整理配置，只改变运行器内存副本，不改应用供应商设置；运行器会包含当前润色偏好。正文质量仍须逐条检查，HTTP 成功不等于忠实性通过。冻结基线、源码 overlay、隔离服务与报告方法见[语音质量基线](../../docs/public/VOICE-QUALITY.md)。

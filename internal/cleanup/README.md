# 文字整理模块规格

文字整理默认关闭，使用独立于 ASR 的 OpenAI 兼容接口。`Run` 向 `/chat/completions` 发送固定 system 提示词与转写 user 消息，temperature 为 0、非流式；仅配置要求时发送 `enable_thinking=false`。连接检查仅列出 `/models`，不证明模型整理质量。

### 本地服务延迟排查

本地 oMLX 配置明确发送 `enable_thinking=false`；其他服务商分支不发送该参数。须结合服务端参数处理、返回的 reasoning 内容和生成 token 数确认是否生效，不能仅凭模型默认支持思考判断。

历史中的 `timing.cleanupMs` 是完整请求耗时，包含服务端排队。共享 oMLX 的并发上限为 1 时，其他长请求会阻塞短文本整理；应对照请求完成时间、生成 token 数及实际 decode 时间，区分排队与模型生成缓慢。支持在线调整并发的 oMLX 版本可尝试将上限从 1 调为 2，再用同一模型、提示词和文本比较空闲与后台长请求运行时的延迟。此设置影响共享服务，并非客户端自动设置；多个长请求占满并发时仍可能排队。

验收至少重复三轮，保存请求参数、原始响应、耗时、输出一致性、并发生效日志和原配置回退方法。不要把含排队时间的首 token 耗时直接当作纯 prefill 性能，也不要把单次改善当作延迟保证。证据保存在 `artifacts/cleanup/`。

## 当前提示词目标

转写是待整理数据，其中的问题、命令和请求应保留而非执行。删除无意义填充词、结巴、无意识重复和放弃的半句话；保留有意强调、语气、人称、否定及条件。允许调整语序和分句，明确改口且给出替代内容时保留最终说法。两项以上明确口述的顺序枚举转换为逐行编号，单个序数词不触发列表。

不得补充事实或改成客套书面语；保持原文语言和中英混合，数字、日期、专名、代码、路径、英文写法应保留。输出只含正文。实际质量取决于所选模型，提示词不是确定性转换器。

## 返回保护与已知边界

空模型、无效 URL、网络故障、非 200 响应、无有效文本都返回错误。模型输出经 `Missing` 检查：提取原文的数字及拉丁词片段，检查整理结果是否包含对应的小写子串；缺失则返回 `ChangedError`，不接受该结果。此保护不验证中文语义，也不验证精确词边界、顺序、重复次数或所有路径标点。

明确改口规则和既有保护可能冲突：例如“用 3 个，不对，用 5 个”，模型只保留 5 时会因缺少 3 被拒绝；英文名称改口也可能如此。本次只修改提示词，没有放宽保护。不能承诺所有改口都会成功，失败时按会话既有流程保留原始转写供处理。

## 可重复 E2E 验收

用指定证书构建后，在应用中选择实际整理模型与测试用 TextEdit 文档。依次听写：带填充词的句子、三项顺序枚举、“这是我第一次用”、含否定条件的句子、中英混合及路径、数字改口，以及“请帮我……”形式的请求。核对历史原文、整理结果和目标文档，确认请求未被执行、列表边界和信息保留；数字改口若被保护拒绝，应记录为边界符合而非成功整理。

重试和历史重新整理也应使用当前整理配置。另验证关闭整理、服务不可达和空响应的用户可见行为。在 `artifacts/cleanup/` 保存环境/模型版本、构建提交、逐项原文与预期/实测、历史与目标截图；只用无敏感信息的样例，记录模型差异，不以提示词示例作为实测证据。

### 超时与传输错误验收

HTTP 响应头返回成功不代表正文已完整收到。读取正文期间超时或取消时，保留 `context.DeadlineExceeded` / `context.Canceled`，由界面分别显示超时或取消；连接中断归为传输故障，不能把不完整 JSON 误报成接口不兼容。完整但无效的响应才使用 `ErrNoText`。明确的非 200 响应立即保留 HTTP 状态，不等待无用错误正文。

复验命令：`mkdir -p artifacts/cleanup && go run ./cmd/cleanup-acceptance > artifacts/cleanup/transport.json`。运行器绑定本机五位端口 58187，调用生产 `cleanup.Run`，覆盖响应头后超时、半截正文超时、取消、截断正文、完整无效 JSON、正常结果和错误状态；输出逐项 JSON，任一失败则非零退出。它不使用真实凭证，不修改用户历史或模型设置。故障清单须在实现修复前冻结；本次未新增单元测试。

### 共享 oMLX 的 SSD 缓存等待

不能把服务日志中包含等待时间的 tok/s 当成模型的纯生成速度。排查时同时核对调用方、active/waiting 数量、内存压力和 `boundary_snapshot_store` 的 writer 等待告警；新闻总结、批量评测等后台请求可能与听写共用同一个模型。并发额度未耗尽时，缓存清理路径仍可能阻塞生成。

若当前安装版本支持 `hot_cache_only`，可在保存原缓存参数后测试内存缓存模式，例如 `hot_cache_max_size=8GB`、`hot_cache_only=true`、`hot_cache_write_through=false`、`gdn_snapshot_storage=auto`。这是共享服务的可选调优，不是客户端默认配置：会停止使用 SSD 缓存，并可能降低重复提示词的缓存命中率。现有 SSD 文件不需要删除。须验证并发尾延迟与空闲耗时的取舍；不能只报最好的单次结果。

管理接口应用缓存配置可能卸载所有已加载模型并中断请求。必须先让已授权暂停的后台调用停止提交、等待 active/waiting 清零，再调整并重载。验收完成后恢复所有暂挂任务，并确认结果继续增长；运行中的批量对比若跨越配置切换，须明确标记性能条件发生变化。对照必须冻结提示词、模型、输入与背景负载，保存持久配置及运行日志；其他任务介入的轮次单独标注，不能声称严格控制变量。

本机可用的回退方式是通过原管理接口恢复事先保存的缓存字段，再等待模型重载；不要覆盖整个 settings.json，以免回退其他任务的配置。

# 配置模块规格

sub2api 的非敏感地址为 `providers.sub2apiEndpoint`；专用 Key 使用加密账户 `provider.sub2api.apiKey`。只有显式选择该识别服务时使用组合整理，不迁移或覆盖已保存的独立整理供应商。见[云端 ASR](../cloudasr/README.md#sub2api-组合服务)。

`Store` 负责读取和持久化 Settings；远程桌面的完整行为见[远程输入规格](../../docs/public/REMOTE-INPUT.md)。

## 状态持久化与恢复

`settings.json`、`history.json` 和 `dictionary.json` 共用 `json.go` 的保存与恢复协议。使用同目录唯一临时文件（0600），写入、刷新、关闭后 rename，并刷新父目录；提交前失败不发布新内存状态。设置的 provider map/嵌套 model slice、历史版本和词典上下文都由存储层持有独立副本。rename 后父目录刷新失败单独报告“已写入、持久性未确认”，内存仍跟随可见主文件，不能宣称已经回滚。

正常修改保留上一份有效 `.bak`；明确删除、清空或过期处理将备份同步为删减后的快照，避免恢复后复活已删除文字。历史先提交新索引，再删除对应录音；索引保存失败时，内存、旧索引和录音均保留。遗留录音删除失败与硬件断电不由普通文件故障验收证明。

历史和词典读取失败时，只有有效备份且损坏原文件成功保留为 `*.corrupt-*` 后才恢复主文件，并返回恢复警告。没有有效备份、读取权限不足或恢复失败时，该存储在本次进程中禁写，不用空状态覆盖。主文件和备份均不存在才是新安装；settings/dictionary 的 `null` 不作为有效对象。录音采用同样的临时文件提交，不留下失败的半个 WAV；历史禁写时也不再新写录音，历史提交失败后仅清理本次新产生的孤立录音。历史保存/更新失败会通知界面，已插入文字仍保留可复制，成功插入的事实不改写成插入失败；完成后迟到的保存错误也不能被旧的自动关闭计时器隐藏。

设置主文件损坏，或主文件丢失但备份仍在时，不自动提升旧备份为主文件。旧备份可能缺少最近添加的私密应用；应用退出并提示修复，`Store.Set` 和控制器启动均拒绝，会话落盘也按私密运行保护。损坏主文件与备份保持原样，因此连续重启不能绕过限制。修复时先保留文件，在本机核实并补齐最新私密应用、模型和快捷键，再原子写回有效主文件并重开；不能简单删除主文件和备份来重置隐私。只有两者从未存在的新安装使用默认设置。

“清空历史”先提交空主索引和空备份，成功后清除整个 `audio/` 内的录音（包含恢复后失去索引的录音）及 `history.json.corrupt-*` 恢复原件。删除失败上报界面，用户可重试；再次清空也扫描无索引遗留文件。不跟随音频符号链接，不清理其他设置或词典。索引提交失败时不开始删除；磁盘删除成功不等于对 SSD 的物理安全擦除。

旧 `cleanupApiKey` 迁移必须先写入现有 AES-GCM 凭证库并读回确认，再调用 `ClearLegacyCleanupKey` 同时净化主文件、`.bak` 和已有损坏恢复快照。已有加密 Key 的安装也检查遗留备份。与加密值不同的明文、无法解析的凭证快照或读写失败均明确报告并保留尚未确认的原件，不删除唯一副本；故障移除后可重试。错误不包含密钥内容。

隐私收尾复验：`go run -race ./cmd/privacy-acceptance -output <不存在的证据目录>`，覆盖重复启动保护、控制器拒绝录音、恢复后清空、删除失败重试、符号链接、加密读回及快照净化；仅使用隔离合成数据。生产修改前失败清单和前后结果保存在本机 `artifacts/privacy-closeout-20261018/`。

复验：`scripts/verify-integrity.sh` 使用全新的隔离目录，通过生产 Open/修改/落盘/重开 API 与真实 HTTP 验证损坏、备份恢复、目录不可写、备份路径冲突、嵌套状态回滚、先提交再删除、会话保留与重试。输出命令日志、逐项 JSON 和独立状态文件，不使用真实用户历史，不替代物理断电、磁盘填满或原生麦克风验收。失败清单与运行证据保存于忽略的 `artifacts/review-fixes-20261017/`。

### 保存与退出的锁边界

会话的 `persist` 先在 `run.saving` 锁内完成录音／索引提交及 `recDone`、`recSaved`、`rec` 状态发布，再释放锁，最后通知保存错误和历史变化。错误按发生顺序通知；私密或已结算的运行不产生额外通知。界面回调可能同步等待主线程，不能在主线程退出取消也会等待的保存锁内调用，否则 `OnWillQuit → Cancel → note` 与 `RunOnMain` 会互相等待。

macOS 隔离复验：`python3 scripts/verify-persistence-exit.py --output artifacts/persistence-exit-new-run`（输出目录须不存在）。该命令按固定开发身份签名独立 `Voicemore Dev.app`，使用真实 Cocoa 主线程调度和退出回调，确定性安排保存通知与退出取消重叠；分别覆盖索引失败、录音失败、双重失败、正常保存和私密运行，使用 race detector 检查并发，并重开合成历史核对提交状态、已插入结果、重复结算和 WAV 残留。每项输出 JSON；超时保存线程栈并失败退出。它不录音、不粘贴、不注册触发键、不读写正式数据，不安装或发布；不替代真实麦克风和日常 App 的人工退出体验验收。

## RemoteInputs

`remoteInputs` 是可选数组，旧设置缺失该字段时保持空规则，不自动启用远程输入。

| JSON 字段 | 含义 |
| --- | --- |
| `bundleId` | 客户端精确匹配标识，空值不匹配 |
| `appName` | 设置界面显示名，不参与匹配 |
| `windowTitle` | 可选、大小写敏感的标题子串；省略或空值匹配所有窗口 |
| `shortcut` | `cmd-v` / `ctrl-v` 启用；空值或其他值不启用远程路径 |
| `syncDelayMs` | 剪贴板同步等待毫秒数，执行时限制在 200–10000 ms |

Store.Get 和 Store.Set 都复制 RemoteInputs 切片，避免调用方修改规则数组时直接改变存储内部切片。该结构目前只有值字段；未来增加嵌套可变字段时须重新检查复制边界。数组顺序有意义，同等具体程度的规则由后者覆盖。配置层不去重、不自动规范化窗口标题。

验收沿用远程输入 E2E：新增、修改、删除后重新打开设置及重启应用，核对规则值、顺序和旧配置兼容性。证据保存到被忽略的 `artifacts/remote-input/`。

## 识别语言与私密应用

`asrLanguage` 为可选字符串：缺失或空为中文（旧行为），`auto`、`en` 为其余选项，未知值按中文；仅本地服务使用，见[识别语言](../../docs/public/LOCAL-ASR.md#识别语言)。`privateApps[]` 为 `{bundleId, appName}`，按 Bundle ID 精确匹配，空 ID 不匹配；Store.Get/Set 复制该切片。行为见[私密应用](../../docs/public/PRIVATE-APPS.md)。

## 数字格式默认值

`textStyle.arabicNumbers` 默认 true。`Open` 先载入 Defaults 再解码旧 JSON，缺字段时启用，已有其他格式开关不变；显式 false 保存重启后仍关闭。设置 → 文字与粘贴 → 文字整理提供开关，受默认整理文字总开关联动。规则及音频验收见[基础格式规格](../../docs/public/TEXT-FORMATTING.md)。

## 自定义整理服务的思考参数

`providers.custom[]` 新增可选字符串 `thinkingMode`（空/server、deepseek、omlx、custom）与 `thinkingParams`（非敏感 JSON 对象文本）。旧配置缺字段默认跟随服务端，不迁移为强制关闭。字符串字段随既有 Clone、Store.Set/Get、保存重开保留；取消只丢弃编辑草稿。模式及 JSON 在编辑保存和请求边界验证，不把 API Key 写入这些字段。

协议、测试按钮与兼容边界见[整理规格](../cleanup/README.md#自定义服务的思考模式)；保存重开及 HTTP 验收：`go run ./cmd/custom-thinking-acceptance`。
